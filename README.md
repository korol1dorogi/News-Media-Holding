# Сигнал

Находит событие в потоке постов за минуты, собирает досье с проверкой на фейк и готовит черновик под формат издания (Mash, Life, Super), где каждое утверждение сверено с источниками. Публикует редактор.
Запуск: `cp .env.example .env && make setup && make run`, затем http://localhost:5173 (нужны Python 3.12, Node из `.nvmrc`, make; на Windows — WSL2).
Все данные синтетические: город, каналы и посты вымышлены. LLM по умолчанию — офлайн-заглушка, сеть и ключи не нужны.

## Замеры

Из [`reports/metrics.md`](reports/metrics.md), генерирует `make eval` на `data/synthetic` (531 пост за 48 часов, 6 демо-событий в шуме):

| Метрика | Значение |
|---|---|
| Демо-событий найдено | 6 из 6, полнота и чистота кластеров 100% |
| От первого поста до появления в ленте | медиана 10 мин, максимум 17 мин модельного времени |
| Уровень досье совпал с разметкой | 6 из 6 |
| Первоисточник и число независимых источников | 6 из 6 |
| Сверка утверждений | ошибка поймана в 3 черновиках из 3, ложных тревог 0 на 15 остальных |
| Вызовов LLM | 0 на ленту (модель вызывается только по кнопке), 1 на черновик |

Абляции показывают, что каждая проверка ловит свой фейк: без первоисточника слух становится зелёным,
без погоды — снегопад, без официальных каналов — опровергнутый пожар, без архива «наводнение»
падает с красного до жёлтого.

## Как это работает

```
посты TG-пабликов, официальных каналов, бота читателей   (в MVP — replay синтетики)
        │
        ▼
normalize ── гео по словарю города, тема по ключевым словам
        │
        ▼
cluster ──── посты → события: гео + тема + окно времени, TF-IDF для постов без гео,
        │    пересылки всегда в кластер оригинала
        ▼
score ────── новостность отдельно для Mash, Life, Super (тема, место, охват, скорость, фото)
        │
        ▼
verify ───── досье-светофор:
        │      • первоисточник и граф репостов, копии без пересылки = тот же источник
        │      • фото против архива по pHash (устойчиво к пережатию и обрезке)
        │      • сцена на фото против погоды и времени суток
        │      • подтверждение или опровержение официальным каналом
        │      итог: зелёный / жёлтый / красный + «что проверить руками»
        ▼
draft ────── по кнопке редактора: черновик под издание, посты в промте помечены как данные
        │
        ▼
claims ───── числа (и словами), даты, время, места, названия сверяются с постами;
             неподтверждённое подсвечено. Публикует только человек.
        │
        ▼
watchdog ─── после публикации следит за официальными каналами: опровержение → алерт
             «обновить или снять»
```

Код: Python 3.12, FastAPI, SQLite, scikit-learn, imagehash; интерфейс — React, Vite, TypeScript,
Tailwind. Пакет [`radar/`](radar), контракт данных — [`radar/core/models.py`](radar/core/models.py).

## Честные ограничения

- Данные синтетические, поток — replay, а не живой сбор.
- Признаки фото (снег, дождь, день) берутся из разметки, а не из vision-модели.
- Черновики по умолчанию пишет детерминированная заглушка; OpenAI-совместимая модель
  (например, открытая модель через Ollama) подключается через `LLM_PROVIDER=openai` в `.env`.
- Веса скоринга заданы вручную, а не обучены на архиве издания.

Каждое упрощение и путь в продакшен — в [`docs/assumptions.md`](docs/assumptions.md).

## Команды

| Команда | Что делает |
|---|---|
| `make setup` | виртуальное окружение, Python- и npm-зависимости |
| `make run` | API на :8000 и интерфейс на :5173, при первом запуске собирает базу |
| `make reset` | пересобрать базу из `data/synthetic` |
| `make eval` | замеры в `reports/metrics.json` и `reports/metrics.md` |
| `make check` | ruff, pytest, проверка типов и сборка фронта |
| `make gen-data` | пересоздать синтетику (детерминированно) |
