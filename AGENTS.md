## 1. Что за проект

«Сигнал» (Python-пакет `radar`) — тестовое задание для отбора на AI-хакатон
News Media Holding × МГТУ им. Н. Э. Баумана.

Система находит событие в потоке постов (TG-паблики, официальные каналы, бот читателей)
и собирает досье с проверкой на фейк. Проверки:
- первоисточник и граф репостов;
- совпадение медиа с архивом по pHash;
- сверка с погодой;
- подтверждение официальным каналом.

Итог досье — светофор. Потом система готовит черновик под формат издания (mash, life, super),
где утверждения сверены с источниками. Публикует человек.

Данные синтетические: вымышленный город, вымышленные каналы.

## 4. Порядок работы

1. План: файлы, функции, тесты, как проверишь критерий готовности. Жди «ок» человека.
2. `git switch main && git pull && git switch -c {ID}`.
3. Маленькие коммиты вида `{ID}: что сделано`.
4. `make check` зелёный.
5. PR по шаблону (`.github/pull_request_template.md`) с выводом проверок. Мержит только лид.

## 5. Качество

- Чистые функции: на входе модели из `models.py`, на выходе модели из `models.py`.
- Какие посты передаются:
  - в `verify.*` и `score.score` — все посты replay; посты события ищи по `event.post_ids`;
  - в `draft.*` — только посты события.
- Детерминизм: фиксированный seed, стабильная сортировка. Одинаковый вход — одинаковый выход.
- Нельзя посчитать — статус `"n/a"` и причина в `summary`, а не выдуманное значение.
- Каждая проверка досье объясняет себя одной фразой (`summary`) и даёт `evidence`
  со ссылкой на пост или архивную запись.
- Тесты проверяют критерий из `docs/tasks.md` на фикстурах или синтетике.
- Тесты не подгоняются под код. Проверки не отключаются (`skip`, `noqa`, ослабленные
  `assert` — только с согласия лида).
